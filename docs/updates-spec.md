# Updates specification and test vectors

The Mac app is the specification (`../menew/Sources/Menew/Updater.swift`, `scripts/appcast.sh`,
`.github/workflows/release.yml`, `Resources/Info.plist`). This file says what Sparkle does on the Mac, what the
Linux port does for each part, and lists the vectors. The tables in "Vectors" are **executed**:
`crates/menew-core/tests/updates_spec.rs` reads this file, runs every row through the real Linux code and
compares the result; the test also fails if it executes a different number of rows than the file has. The
expected values were derived by hand from the rules below (SemVer 2.0 and the Mac behaviour), not copied
from the Linux output.

In a table cell `-` is "nothing / none" and lists are joined with `¶`. Cells never contain a pipe character.

## What the Mac does and what Linux does

| Part | Mac (Sparkle) | Linux |
|---|---|---|
| Automatic check | On by default (`SUEnableAutomaticChecks`), toggle in Settings, `automaticallyChecksForUpdates` | On by default, `auto_update_check` in `config.json` and a checkmark item in the tray (the settings window comes in Phase 11) |
| Interval | `SUScheduledCheckInterval` 86400 s | 86400 s (`AUTO_CHECK_INTERVAL_SECS`), first check 300 s after the daemon starts (`STARTUP_CHECK_DELAY_SECS`) |
| Discreet reminder | "Gentle reminders": `standardUserDriverShouldHandleShowingScheduledUpdate` returns false, a dot on the icon, no window | A scheduled check never opens a window and never notifies: the tray icon gets the "needs attention" status with an overlay icon and the menu gets "Update available: X" |
| Manual check | "Check for Updates…" opens the window or says up to date | "Check for Updates…" in the tray and the palette: window if found, a notification "Menew is up to date" or "Could not check for updates" otherwise; if an update is already pending it opens its window |
| Window | Release notes (HTML of the appcast turned into text), buttons Install and Relaunch / Later (Sparkle adds Skip This Version) | `adw::MessageDialog` with the notes of the CHANGELOG section as plain text (`plain_notes`) and Install and Relaunch / Skip This Version / Later |
| Skip a version | Sparkle remembers it, the automatic check stays quiet about that version | `skipped` in `~/.config/menew/update-state.json`; automatic checks stay quiet about exactly that version, a manual check still shows it |
| Install | Downloads, installs on quit or on "Install and Relaunch", asks the admin password when needed | AppImage: replaced in place and restarted. `.deb`: `pkexec apt-get install -y <file>` (polkit asks the password) and restarted. Other: only a notification with the link of the release |
| `--snapshot` | No Sparkle (`UpdaterModel(enabled: false)`) | The snapshot never builds the updater, so nothing is requested. Under `MENEW_TEST=1` a check needs an explicit `MENEW_UPDATE_FEED` |
| Feed | `SUFeedURL` = `.../releases/latest/download/appcast.xml`, generated by `scripts/appcast.sh` | The GitHub API listing of the releases plus the `update.json` of the chosen release, generated and signed by `scripts/make-update-json.sh` in the `Release` workflow |
| Signature | EdDSA (`SUPublicEDKey`, private key in the `SPARKLE_PRIVATE_KEY` secret) | Ed25519 with a **Linux-only key pair**: public key in `UPDATE_PUBLIC_KEY` (`menew-core`), private key in the `MENEW_UPDATE_SIGNING_KEY` secret. Required: unsigned or wrongly signed files are never installed |
| Notes | From the version's section of `CHANGELOG.md` through the GitHub Markdown API | From the same section, kept as Markdown in `update.json` and shown as plain text |

## The feed

1. `GET https://api.github.com/repos/Quost/menew-linux/releases?per_page=10` (no token, `User-Agent: Menew/<version>`).
   `releases/latest` is not used because it ignores pre-releases and every release of the alpha is one.
2. Drafts, tags that are not versions and releases without an `update.json` asset are dropped.
3. The highest version **greater than the running one** wins. A stable running version ignores pre-releases
   (by the SemVer suffix or by the GitHub `prerelease` flag); a pre-release running version follows them too.
4. `GET` the `update.json` of that release. Its `version` must equal the version of the release.

`update.json`:

```json
{
  "version": "0.1.0-alpha.2",
  "date": "2026-11-20",
  "notes": "- **Palette**: ...",
  "artifacts": {
    "appimage": { "url": "https://github.com/Quost/menew-linux/releases/download/v0.1.0-alpha.2/Menew-0.1.0-alpha.2-x86_64.AppImage",
                  "size": 12345678, "sha256": "<64 hex>", "signature": "<base64 of 64 bytes>" },
    "deb":      { "url": "https://github.com/Quost/menew-linux/releases/download/v0.1.0-alpha.2/menew_0.1.0-alpha.2_amd64.deb",
                  "size": 1234567, "sha256": "<64 hex>", "signature": "<base64 of 64 bytes>" }
  }
}
```

### What is signed

The signature is **not** over the file itself but over this text (`signed_message`):

```
menew-update\nversion=<version>\nartifact=<appimage|deb>\nsize=<bytes>\nsha256=<hex>\n
```

The file is bound by its SHA-256 and size, which the app checks on the downloaded file; the version and the
kind are bound by the signature. So an old, validly signed file cannot be offered as a new version
(rollback), and the AppImage cannot be swapped for the `.deb`. It also keeps the signing step cheap
(`openssl pkeyutl -sign -rawin` on a 100 byte file) and the verification independent of the file size.

### Verification order

Size, then SHA-256, then the signature; the first failure refuses the update and the downloaded file is deleted.
Nothing is installed before all three pass.

## Differences (also in `docs/parity.md`)

- Sparkle updates the `.app` bundle; Linux has two package formats and a third case (built from source) that
  can only be told about.
- No delta updates and no "install on quit": the update is applied when the user picks Install and Relaunch.
- Restart starts the new Menew with **no arguments** (a first launch: the palette stays hidden) instead of
  repeating the arguments of the old process, because the arguments of a daemon are usually a command
  (`menew clipboard`) that should not run again.

## Not covered by vectors (checked end to end, see the summary of the work)

- The real download, replacement of an AppImage on disk and restart: `menew check-updates --install` and the daemon
  against a local server with a test key.
- The `.deb` path with a simulated `pkexec`.
- The `Release` workflow signing step (`scripts/make-update-json.sh`) with a test key.
- The window and the tray dot (GNOME and KDE headless sessions).
